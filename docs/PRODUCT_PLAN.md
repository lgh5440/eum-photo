# 이음 포토 기획안

작성일: 2026-05-08

## 한 줄 정의

이음 포토는 교회학교 교사들이 행사 사진을 빠르게 모으고, 선별하고, 학생/부서/반/행사 기준으로 안전하게 정리하도록 돕는 로컬 우선 사진 업무 도구다.

## 개발 필요성

기존 사진 프로그램은 사진 자체를 잘 다루지만, 교회학교 교사의 실제 업무 흐름에는 빈틈이 있다.

- 이번 행사 사진인지 구분해야 한다.
- 어느 부서/반/학생 사진인지 정리해야 한다.
- 학부모 공유용, 교회 보고용, 내부 보관용을 나눠야 한다.
- 공개하면 안 되는 학생이나 사진을 검토해야 한다.
- 여러 교사가 찍은 사진을 한곳에 모아야 한다.
- 원본 사진은 이음 서버가 아니라 교회/교사/사용자 저장소에 둬야 한다.

따라서 일반 사진관리 앱을 대체하는 것이 아니라, 교회학교 사진 업무에 특화된 보조도구로 개발한다.

## 기존 프로그램과의 비교

| 구분 | 기존 프로그램 | 이음 포토 |
| :--- | :--- | :--- |
| Google Photos/Drive | 모바일 백업과 공유가 강함 | 부서/반/학생/행사 기준 정리 특화 |
| Apple Photos/iCloud | iPhone 개인 사진 관리에 강함 | Windows/Android/교회 공동 업무 고려 |
| Mylio Photos | 로컬 우선 동기화와 얼굴 태그가 강함 | 교회학교 업무 흐름을 무료/저비용으로 단순화 |
| digiKam | 무료 고급 사진 관리 | 교사용 쉬운 화면과 행사 정리 흐름 제공 |
| XnView | 빠른 보기와 일괄 변경 | 초상권/공개/학생 태그 흐름 보강 |
| Lightroom/ACDSee/Excire | 전문가용 선별/보정/AI 검색 | 보정이 아니라 교사 업무 정리에 집중 |

## 개발 필요성 평가

- 일반 사진관리 앱을 새로 만드는 관점: 4/10
- 교회학교 사진 업무 전용 도구 관점: 8/10

핵심은 기존 제품과 경쟁하지 않는 것이다. 이음 포토는 사진 보관소가 아니라 사진 업무 정리 도구다.

## 사용자

- 교회학교 교사
- 부서 사진 담당자
- 수련회/성경학교/행사 운영팀
- 홍보·보고 자료를 정리해야 하는 교역자 또는 부장

## 핵심 원칙

1. 사진 원본은 서버에 저장하지 않는다.
2. 사용자가 선택한 저장소에 보관한다.
3. 처음에는 독립 프로그램으로 개발한다.
4. 이음 스쿨 연동은 후속 단계로 둔다.
5. 자동 판단은 후보 제안까지만 하고, 최종 판단은 교사가 한다.

## 저장 방식 방향

### 1단계: 웹/PWA

- 사진 선택 또는 드래그 앤 드롭
- 빠른 선별
- 행사명/학생명 태그
- 대표 인물 폴더 만들기
- 정리본 ZIP 다운로드
- 정리안 CSV/JSON 내보내기

### 2단계: 데스크탑 저장

- 사용자가 선택한 컴퓨터 폴더에 실제 폴더 생성
- 파일 복사
- 파일명 일괄 변경
- 대량 사진 처리 안정화

### 3단계: Google Drive 저장

- Google Drive 폴더 선택
- 행사별 폴더 생성
- 정리된 사진 업로드
- 모바일과 컴퓨터의 연결 저장소로 활용

## 개발 전략

처음부터 전체 사진관리 앱을 만들지 않는다. 다음 문장에 집중한다.

> 행사 사진을 빨리 모으고, 학생/반/부서별로 안전하게 정리하고, 공개 가능한 사진만 추려내는 도구.

이 범위를 지키면 기존 프로그램보다 작지만, 교사에게는 더 직접적으로 도움이 되는 제품이 된다.

## 개발 로그

### 2026-05-08

- 확대 보기에서 검출된 얼굴 박스를 선택할 수 있게 한다.
- 선택한 얼굴에 이름을 입력하면 대표 사진이 지정된 인물 폴더가 바로 생성된다.
- 이 기능은 완전 자동 얼굴 인식 전 단계로, 교사가 수동 확인을 하면서도 인물별 정리 속도를 높이기 위한 흐름이다.
- 작업 저장 JSON과 작업 불러오기 기능을 추가해 같은 원본 사진을 다시 넣으면 태그, 상태, 인물 폴더, 얼굴 박스를 복원한다.
- 학생 명단 CSV를 불러와 이름 버튼으로 선택 사진에 빠르게 학생 태그를 붙일 수 있게 한다.
- PWA manifest와 서비스 워커 기본 캐시를 추가해 데스크탑/모바일 설치형 사용의 기반을 만든다.
- 공개 후보 이름 미지정, 대표 사진 흐림/중복, 인물 없음 같은 최종 검토 항목을 자동 표시한다.
- Chrome/Edge 지원 환경에서 선택한 로컬 폴더에 행사/상태/인물별 하위 폴더와 정리안 CSV를 직접 저장한다.
- 인물 후보에 유사도 점수를 표시하고 작업 JSON에 후보 점수도 저장한다.
- 교사용 테스트 시나리오와 학생 명단 샘플 CSV를 추가한다.
- 정리안 JSON export를 추가해 행사 요약, 인물 폴더 요약, 사진별 권장 폴더·파일명을 구조화된 형태로 내보낸다. ZIP과 로컬 폴더 저장에도 `_정리안.json`을 함께 동봉해 이음 스쿨이나 다른 도구로 import할 수 있게 한다.
- 학생 명단 매칭 미리보기를 추가한다. 명단 칩에 매칭 사진 수 배지를 표시하고, 매칭/미매칭/명단 외 태그를 색으로 구분한다. 정리안 JSON에도 rosterMatch 요약을 함께 저장한다.
- 행사 단위 누적 통계를 localStorage에 보관한다. `이 행사 누적에 추가` 버튼을 누르면 학생별 사진 수가 행사 간 합산되어 학생별 등장 균형을 비교할 수 있다.
- 명단 CSV에 `공개동의/초상권/consent` 컬럼이 있으면 이름별 동의 상태(예/아니오/미확인)를 읽고, 명단 칩에 ✓/✗/? 표식과 색을 적용한다. 공개 후보 사진에 미동의 학생이 포함되면 검토 필요 항목이 자동 표시되고 정리안 JSON에도 사진별 consent 블록이 포함된다.
- Google Drive 저장을 옵션 기능으로 추가한다. `VITE_GOOGLE_CLIENT_ID` 환경변수가 설정된 경우에만 버튼이 보이며, drive.file 범위만 사용해 행사 폴더와 행사/상태/인물 하위 구조 + `_정리안.csv`/`_정리안.json`을 업로드한다.
